Domain embedding configuration guide

This guide remains available because the editor saves JSON, which does not retain YAML comments.

What a domain controls

Each entry under domains selects a knowledge base, embedding model, vector format, and retrieval strategy. active_domain selects the default at startup; ACTIVE_DOMAIN in .env overrides it.

Required fields

collection_name
The Qdrant collection that stores this domain’s vectors.
embedding_model_key
For example, openai:embed_small, gemini:native-embed, or local:dense_default.
model_type
hosted for provider-backed embeddings; local for FastEmbed models.
vector_type
null for the legacy unnamed dense vector, dense for a named dense vector, or hybrid for named dense plus SPLADE sparse vectors.
search_mode
Use dense for dense configurations and hybrid with vector_type: hybrid.

Collection compatibility

Keep an embedding model paired with a compatible collection. Qdrant fixes vector dimensions when a collection is created: openai:embed_small is 1536D, while local:dense_default is 768D. Do not point a changed model at an incompatible existing collection.

If you change a model, vector type, or vector dimension, use a new collection or recreate the old one in Admin → Manage collections, then re-index the domain. Recreating permanently removes that collection’s indexed data.

Hybrid retrieval

hybrid stores a dense vector and a SPLADE sparse vector, and requires search_mode: hybrid. SPLADE is loaded locally during hybrid indexing and search even when the dense embedding model is hosted.

Starting example

{
  "active_domain": "my_domain",
  "domains": {
    "my_domain": {
      "collection_name": "document_index_my_domain",
      "embedding_model_key": "local:dense_default",
      "model_type": "local",
      "vector_type": "hybrid",
      "search_mode": "hybrid"
    }
  }
}
